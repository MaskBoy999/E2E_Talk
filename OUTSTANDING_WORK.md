## R2. PQ ships, and A5 (the re-keying sweep) must be added and tested

**Requirement:** post-quantum envelopes and login **do** ship. Lazy re-keying is **not**
acceptable — the sweep must exist and be covered by a test.

**What already exists (verified in `origin/test`):**

- Hybrid key envelopes: X25519 + ML-KEM-768, packed `v2:` ciphertext, `v1` still readable.
  `server/src/db.rs` `encrypt_notification_payload`, `static/crypto.js` `envelopeEncrypt`.
- Hybrid login: Ed25519 + ML-DSA-65 over a server nonce. `server/src/main.rs`
  `verify_login_signature` / `decode_login_key_set` / `verify_ml_dsa_65`.
- Cross-language KATs: `server/tests/fixtures/pq-kat.json`, generated by
  `tools/gen-pq-kat.mjs`, asserted by Rust (`server/src/main.rs`) **and** in the browser by
  `tests/pq-envelopes.spec.ts`.
- Hybrid TLS: `tests/pq-envelopes.spec.ts` asserts `openssl s_client -groups X25519MLKEM768`
  negotiates the hybrid group.
- **Envelope half of the sweep already works:** `static/chat.js`
  `publishIdentityPqKeyIfNeeded()` runs on the heartbeat, compares
  `identity_pq_public_key`, and POSTs `/api/identity/pq-key` when it differs. Derived
  deterministically, so it is idempotent across devices.

**The gap — the login half has no sweep.** A v1 (bare Ed25519) account never upgrades:

| Login key written by | Upgrades to v2? |
|---|---|
| `register` — `server/src/handlers.rs` (~1188) | yes, hybrid required |
| `change_password` — `server/src/handlers.rs` (~2247) | yes, hybrid required |
| **`login` — `server/src/handlers.rs` (~1370–1390)** | **no — verifies only, never writes** |

And `static/crypto.js` `loginRequestBody()` only attaches `login_pq_signature` when the
*stored* key already starts with `{` (v2 JSON). So a legacy account signs with Ed25519
alone forever, leaving recorded login signatures quantum-vulnerable — the exact
harvest-now-decrypt-later hole this work exists to close.

**Implementation (everything needed already exists):**

1. `static/crypto.js` — `deriveLoginPublicKeyBundle(hashKeyBytes, password)` already
   returns `{v:2, ed25519, ml_dsa_65}`. No new crypto.
2. `static/crypto.js` `loginRequestBody()` — when `params.login_public_key` is a bare key
   (does not start with `{`), also attach `login_public_key: deriveLoginPublicKeyBundle(...)`.
3. `server/src/handlers.rs` `LoginRequest` — add the optional field.
4. `server/src/handlers.rs` `login` — **only after** `valid` is computed from the *old*
   key, if the request carries a v2 bundle and the stored key was v1, persist it with
   `set_login_public_key`. Doing this before verification is an account-takeover primitive.
5. Test — register a v1-shaped key directly (the pattern `tests/security-hardening-f.spec.ts`
   already uses), log in, assert `/api/auth-params` now returns a `{v:2,…}` blob, and
   assert a subsequent login **without** `login_pq_signature` is refused.

Also required by the same decision: **no legacy fallbacks anywhere.** Confirmed already
enforced — `verify_user_verifier` accepts only `$e2e$…` and `verifier_needs_upgrade` was
deleted. Keep it that way; the app is in development and there are no real users.

## Deliberate decisions — do NOT reopen

Confirmed by the owner on 2026-11-07. These are settled; treat any suggestion to reverse
them as a regression, not an improvement.

| Decision | Rationale (owner's words, in substance) |
|---|---|
| **No auto-updater** | An updater is a code-execution path: if the developer's project is compromised, the update channel ships malware to every install. Manual re-download only. |
| **No macOS / iOS** | Too hard for the value delivered. Apple users use the web app in a browser — it is fully supported there. |
| **No APNs** | Follows from dropping iOS. |
| **LiveKit SFU (7.3) deferred** | Its own future session: needs the key-derivation ⟷ FrameCryptor check and the fail-closed signalling guarantee. |
| **No legacy fallbacks at all** | The app is in development and there are no real users, so nothing needs a compatibility path. Any legacy acceptance path is a bug. |
| **Voice features use the existing relay/mesh** | `VOICE_CALLS_SPEC.md` describes a mediasoup SFU that was never adopted; the spec is reference material, not a plan. Do not "fix" the code to match it. |
