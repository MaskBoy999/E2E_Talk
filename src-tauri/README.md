# E2E Chat — Website in a Box (Tauri 2)

The native desktop shell. It wraps the existing web app (`static/`, served by the
Rust server) in the OS WebView — no browser chrome, plus a tray, auto-start and a
first-run setup screen for the host's Tailscale address.

See `WEBSITE_IN_A_BOX_MASTER_PLAN.md` at the repo root for the full design.

## Layout

```
src-tauri/
├── Cargo.toml                 # tauri + notification + autostart, tray feature
├── tauri.conf.json            # frontendDist ../static, withGlobalTauri
├── capabilities/default.json  # minimal allowlist (core, notification, autostart)
├── icons/icon.png, icon.ico   # generated by tools/box/make-icons.mjs
└── src/
    ├── main.rs                # entry point
    ├── lib.rs                 # startup routing, tray, IPC commands
    └── config.rs              # server URL + preferences on disk
```

The first-run UI is `static/box-setup.html` (bundled as the local `setup` window).

## Commands (IPC)

| Command | Purpose |
|---|---|
| `get_config` | Read the saved server URL + preferences |
| `test_connection { url }` | Reachability probe for the setup screen |
| `save_config { serverUrl, autoStart, minimizeToTray }` | Persist, apply auto-start, open the app window |
| `show_setup` | Re-open the setup window |
| `quit_app` | Quit |

## Dev / build

Install the Tauri CLI once: `cargo install tauri-cli --locked`.

```bash
# Dev — opens a native window pointing at the local server (devUrl)
# Start the server first (see the repo's start-server script), then:
cargo tauri dev

# Installers for the current OS
cargo tauri build
```

`cargo check` works without the CLI and is what CI runs first.

## Behaviour

- **First launch** (no `config.json`) → the setup window. Enter the host's
  Tailscale address, Test connection, Save & Launch.
- **Later launches** → the main window opens directly at the saved address.
- **Close** hides to the tray (unless "Minimize to tray on close" was unchecked).
- **Tray** → Show E2E Chat · Change Server Address… · Quit.
- Config lives under the OS per-app config dir, e.g.
  `%APPDATA%/com.e2echat.app/config.json`.

## Regenerate icons

```bash
node tools/box/make-icons.mjs          # PNG + ICO, no dependencies
# or, with the Tauri CLI, for the full platform set:
cargo tauri icon static/icons/icon-192.svg
```

## Android

The same crate builds for Android. `src/lib.rs` already:
- carries `#[cfg_attr(mobile, tauri::mobile_entry_point)]`,
- gates the desktop-only pieces (tray, auto-start, close-to-tray) behind `cfg(desktop)`,
- grants the configured host access to the `notify` command at runtime
  (`dynamic-acl` + `CapabilityBuilder`), so notifications work on the remote page.

```bash
# one-time: Android SDK + NDK + Java 17 must be installed
cargo install tauri-cli --locked
cd src-tauri && cargo tauri android init

# then follow android-templates/README.md (Gradle module + notification permission)

cargo tauri android build --apk
# → gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

The APK is sideloadable (enable "Install unknown apps"); for a Play-Store-style
install you'd need a signing key and a release build.

### `plugins/call-service/`

Keeps a voice call alive with the screen off. `lib.rs` registers it; the actual work
is Kotlin (`android/src/main/java/com/e2echat/callservice/`): the plugin's `start`/`stop`
commands drive a `mediaCall` foreground service, and the plugin ships its own
`AndroidManifest.xml` so the service declaration is not a manual edit in `gen/android/`.
It is inert on desktop — calls there already survive a minimised window.

```bash
cargo check --manifest-path src-tauri/plugins/call-service/Cargo.toml
```

`static/voice.js` calls it from `_boxCallService()` on call join and on every room
teardown, guarded by `window.__TAURI__` and an Android user-agent check.
