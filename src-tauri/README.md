# E2E Chat — Website in a Box (Tauri 2)

The native desktop shell. It wraps the existing web app (`static/`, served by the
Rust server) in the OS WebView — no browser chrome, plus a tray, auto-start,
first-run setup for the host's Tailscale address, and TOFU certificate pinning.
There is deliberately **no auto-updater** — updates are manual re-downloads.

See `WEBSITE_IN_A_BOX_MASTER_PLAN.md` at the repo root for the full design.

## Layout

```
src-tauri/
├── Cargo.toml                 # tauri + notification + autostart, tray feature
├── tauri.conf.json            # frontendDist ../static, withGlobalTauri, bundle config
├── capabilities/default.json  # minimal allowlist (core, notification, autostart)
├── icons/icon.png, icon.ico   # generated by tools/box/make-icons.mjs
└── src/
    ├── main.rs                # entry point
    ├── lib.rs                 # startup routing, tray, IPC commands
    ├── config.rs              # server URL + preferences + pinned cert fingerprint
    └── cert_probe.rs          # TOFU: capture/verify the host certificate fingerprint
```

The first-run UI is `static/box-setup.html` (bundled as the local `setup` window).

## Commands (IPC)

| Command | Purpose |
|---|---|
| `get_config` | Read the saved server URL + preferences (+ pinned fingerprint) |
| `test_connection { url }` | Reachability probe for the setup screen (verifies the pin) |
| `probe_certificate { url }` | Return the host's leaf-cert SHA-256 so setup can show/pin it |
| `save_config { serverUrl, autoStart, minimizeToTray, pinCert }` | Persist, pin the cert, apply auto-start, open the app window |
| `show_setup` | Re-open the setup window (used by the tray *and* by Settings → Connection) |
| `quit_app` | Quit |
| `notify { title, body }` | Native (OS-level) notification |

## Dev / build

Install the Tauri CLI once: `cargo install tauri-cli --locked`.

```bash
# Dev — opens a native window pointing at the local server (devUrl)
# Start the server first (see the repo's start-server script), then:
cargo tauri dev

# Installers for the current OS
cargo tauri build
```

`cargo check` works without the CLI and is what CI runs first.

## Behaviour

- **First launch** (no `config.json`) → the setup window. Enter the host's
  Tailscale address, Test connection, Save & Launch.
- **Later launches** → the main window opens directly at the saved address.
- **Close** hides to the tray (unless "Minimize to tray on close" was unchecked).
- **Tray** (desktop) → Show E2E Chat · Change Server Address… · Quit.
- **Settings → Connection** (any box build, desktop *and* Android) → shows the
  server this app is pointed at and reopens the setup screen. The Android box has
  no tray, so this is the only in-app way to change the address.
- Any **host and port** are accepted in setup — a missing scheme or port just
  defaults to `https://` and `3443`.
- Config lives under the OS per-app config dir, e.g.
  `%APPDATA%/com.e2echat.app/config.json`.

## Certificate pinning (TOFU)

The server presents a **self-signed** certificate, so the WebPKI trust stores do
not apply. Instead `cert_probe.rs` records the leaf certificate's SHA-256 on first
trust and refuses a different one afterwards:

- setup's **Test connection** shows the fingerprint; **Trust this server's
  certificate** pins it on save (`pinned_cert_sha256` in `config.json`);
- every launch re-probes the host and aborts with a "certificate changed"
  message when the fingerprint moved (`open_main failed … ; opening setup`);
- `test_connection` uses the same verifier, so the reachability check and the
  launch check can never disagree.

Rotated the host cert on purpose? Relaunch, tick **Trust this server's
certificate** again and save.

## Updates — manual, by design

There is **no `tauri-plugin-updater`** (see plan §A3.10). To update, download the
newest installer from <https://github.com/MaskBoy999/E2E_Talk/releases> and run it
(Android: re-install the APK). Nothing in the box checks for updates, so there are
no update-signing keys or secrets to configure — the release pipeline is key-free
apart from the optional Windows code-signing certificate.

## Android

The same crate builds for Android. `src/lib.rs` already:
- carries `#[cfg_attr(mobile, tauri::mobile_entry_point)]`,
- gates the desktop-only pieces (tray, auto-start, close-to-tray) behind `cfg(desktop)`,
- grants the configured host access to the `notify` command at runtime
  (`dynamic-acl` + `CapabilityBuilder`), so notifications work on the remote page.

```bash
# one-time: Android SDK + NDK + Java 17 must be installed
cargo install tauri-cli --locked
cd src-tauri && cargo tauri android init

# then follow android-templates/README.md (Gradle module + notification permission)

cargo tauri android build --apk
# → gen/android/app/build/outputs/apk/universal/release/…-unsigned.apk
```

**A release APK is unsigned** — Tauri only signs when
`gen/android/app/build.gradle.kts` has a `signingConfigs` block, and that whole
project is generated by `android init` (so it can't be committed). Android will
refuse to install an unsigned APK. Two ways round it:

- **CI does the signing for you** (`.github/workflows/android.yml` → *Sign the
  APK*): it signs the built APK with `apksigner`, using your upload keystore when
  the `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`
  secrets exist, and otherwise a throwaway debug keystore so the release download
  is installable. It runs `apksigner verify` afterwards, so an uninstallable APK
  can't be published silently.
- **Locally**, build a debug APK instead (`cargo tauri android build --apk
  --debug`, signed with the standard debug key), or sign a release one by hand:
  ```bash
  keytool -genkeypair -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
  "$ANDROID_HOME/build-tools/34.0.0/apksigner" sign --ks upload.jks --ks-key-alias upload \
      --out app-signed.apk app-universal-release-unsigned.apk
  ```

Install with `adb install -r app-signed.apk`, or copy it to the device and allow
"Install unknown apps".

### `plugins/call-service/`

Keeps a voice call alive with the screen off, and rings incoming calls over the
lock screen. `lib.rs` registers it; the work is Kotlin
(`android/src/main/java/com/e2echat/callservice/`):

- `CallServicePlugin.kt` — `start` / `stop` / `incomingCall` / `cancelIncoming`;
- `CallForegroundService.kt` — the `mediaCall` foreground service + its ongoing
  "In call" notification;
- `IncomingCallNotifier.kt` — the high-importance **full-screen-intent** ring
  (category CALL, ringtone/vibration, a *Decline* action receiver);
- the plugin ships its own `AndroidManifest.xml` (`FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_MEDIA_CALL`, `WAKE_LOCK`, `POST_NOTIFICATIONS`,
  `USE_FULL_SCREEN_INTENT`), so none of it is a manual edit in `gen/android/`.

It is inert on desktop — calls there already survive a minimised window.

```bash
cargo check --manifest-path src-tauri/plugins/call-service/Cargo.toml
```

`static/voice.js` calls it from `_boxCallService()` on call join and on every
room teardown, and from `_boxIncomingCall()` when a ring arrives while the page
is hidden — both guarded by `window.__TAURI__` and an Android user-agent check.

### Push on Android (FCM)

The WebView has no Push API, so Android push needs Firebase. The server side is
ready (`server/src/push.rs` + `/api/push/register`); to switch the Android leg on:

1. create a Firebase project, add an Android app with the package id
   `com.e2echat.app`, and download `google-services.json` into
   `src-tauri/gen/android/app/`;
2. add the `firebase-messaging` Gradle dependency and the google-services plugin
   to the generated Gradle module;
3. hand the token to the web app (`window.__BOX_FCM_TOKEN__`, or a
   `plugin:push-service|getToken` command) — `static/push-client.js` registers it
   automatically and re-registers on `box-fcm-token` events;
4. give the **server** a service-account key: `FCM_SERVICE_ACCOUNT_JSON` = the raw
   JSON or a path to the file you downloaded in step 1 (the old server-key
   endpoint is retired, so the server mints an OAuth2 token instead).

Verify the crypto side with `cd server && cargo test push` (RFC 8291 test vector).

Until then Android push is off; browsers and the desktop box use Web Push
(VAPID), which needs no accounts.
